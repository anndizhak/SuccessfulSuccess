# ADR 0008: The core of SuccessfulSuccess on Google Cloud

- Status: accepted
- Date: 2026-11-14

## Context

Since Lab 7 the app runs on AWS (account 347282156909, us-east-1) and is
described in Terraform (`infra/`, HCP workspace `successfulsuccess-dev`). Lab 9
asks what it would take to run the same system on Google Cloud, and moves its
core there: the frontend, the API and the database. Sign-in, the weekly report
and the agenda parser stay on AWS for now.

Constraints:

- **AWS keeps running unchanged.** Nothing in `infra/` or in the dev workspace
  changes; the GCP side is a separate root module (`gcp/`) with its own state
  (workspace `successfulsuccess-gcp`), so one plan cannot break both clouds.
- **No long-lived keys.** No service account key exists. Locally, the owner's
  own `gcloud` login (application default credentials); HCP Terraform logs in
  through Workload Identity Federation, the same idea as the OIDC role from
  Lab 7.
- **Free Trial.** $300 of credit until 13 February 2027, a $5 budget alert,
  region us-central1. The credit does not pay for Claude on Vertex AI.

## Decision

### Every piece of the AWS architecture, row by row

| Piece on AWS | On Google Cloud | Decision | Why |
| --- | --- | --- | --- |
| S3 + CloudFront (Free plan) + WAF, static export | **Firebase Hosting** | **replace** | CDN and a managed certificate included, free plan. `/api/**` is rewritten to Cloud Run: one origin and no CORS, as CloudFront gave us. Firebase has no WAF; Cloud Armor needs a load balancer that bills by the hour, so the WAF row is dropped for now. |
| Lambda + function URL, FastAPI through Mangum | **Cloud Run** (`meetings-api`) | **replace** | The same Docker image as local development (`backend/Dockerfile`); Mangum is only in the Lambda image now (dependency group `lambda`). Scales to zero, min 0 / max 2 instances, request-based billing. |
| ECR | **Artifact Registry** (`meetings`) | **replace** | Keeps the last three images, well inside the free 0.5 GB. |
| Aurora Serverless v2 (0–1 ACU, pauses) | **Cloud SQL for PostgreSQL 17, db-f1-micro, 10 GB SSD** | **replace** | See *The database* below. |
| `AWS_DB_PASSWORD` (a CloudFormation parameter from `.env`) | **Secret Manager** (`database-url`) | **replace** | The password is generated by Terraform and lives only in the HCP state and in Secret Manager. Only `meetings-api` can read that one secret. |
| IAM roles: Lambda execution roles, the HCP and GitHub OIDC roles | **Service accounts** `terraform` and `meetings-api` + **Workload Identity Federation** | **replace** | One account per program. `terraform` has six admin roles of its own services and `serviceAccountUser` on `meetings-api` only (no Owner, no Editor, no project IAM rights). `meetings-api` has `cloudsql.client` and access to one secret. The WIF condition admits only the HCP organization `org-tFizD3ANLvCs6pT5` and workspace `ws-Kquo9hS82XrQjNL5`: immutable IDs, not names. |
| Terraform `aws` provider, workspace `successfulsuccess-dev` | `google` provider, workspace **`successfulsuccess-gcp`** | **replace** | Same HCL and workflow, a different state. APIs are enabled from Terraform, so a fresh project is reproducible. The identities that Terraform logs in as are made once by `gcp/bootstrap/` with a local state. |
| CloudWatch Logs (30-day retention) | **Cloud Logging** | **replace** | Cloud Run sends stdout there; the default 30-day bucket and the free 50 GiB a month are enough. |
| AWS Budgets alarm (`aws_budgets_budget`) | **Billing budget**, $5 a month, 50/90/100 % | **replace** | Created in the console before anything else. Alerts only, it stops nothing. |
| Cognito user pool + Google sign-in | Identity Platform (Firebase Authentication) | **keep on AWS** (stretch) | See *What we do not move*. |
| EventBridge Scheduler (weekly report) | Cloud Scheduler | **keep on AWS** (stretch) | Part of the weekly report. |
| SQS + dead-letter queue | Pub/Sub (push to Cloud Run) | **keep on AWS** (stretch) | Part of the weekly report. |
| S3 event → mailer Lambda | Cloud Storage + Eventarc → Cloud Run | **keep on AWS** (stretch) | Part of the weekly report. |
| SES (the owner's own Gmail as the identity) | no Google service | **keep** | See *E-mail*. |
| Bedrock (Claude) for Paste an agenda | Vertex AI (Gemini, or Claude through Model Garden) | **keep on AWS** (stretch) | See *What we do not move*. |
| S3 gateway endpoint, VPC, security groups | — | **drop** | Cloud Run reaches Cloud SQL through the Cloud SQL connector (IAM + TLS over the instance's public IP with no authorized networks). No VPC, no serverless VPC connector, no NAT, nothing that bills by the hour. |
| WAF | Cloud Armor | **drop** (for now) | Needs an external Application Load Balancer, about $18 a month before any traffic. |
| GitHub OIDC role for CI deploys | WIF provider for `token.actions.githubusercontent.com` | **later** (stretch) | Its condition would use `repository_id` and `repository_owner_id`, the numeric IDs. Until then the API is deployed from the laptop with `make gcp-deploy`. |

### The database

| Option | Latency | Bill (idle month) | Code |
| --- | --- | --- | --- |
| **Cloud SQL around the clock** (chosen) | Same region as Cloud Run, ~1 ms per query; no cold start of the database | ≈ $9.40: $7.67 compute + $1.70 for 10 GB SSD | None. The same SQLAlchemy models, repositories and Alembic migrations. Only the `DATABASE_URL` changes (a unix socket at `/cloudsql/...`). |
| Cloud SQL stopped at night | Same while running. A stopped instance does **not** start on a connection the way Aurora resumes: requests fail until someone or a schedule starts it, and starting takes minutes | ≈ $1.70 stopped; ≈ $4.50 if it runs 12 h a day | None, but a scheduler (Cloud Scheduler + a call to the Admin API) and an error page while it is down |
| Firestore | Low, serverless, no cold start | ≈ $0 at student traffic (50,000 reads a day free) | A rewrite: models, repositories and migrations become documents designed around each screen's queries. No joins, no foreign keys; the meeting → participants and meeting → agenda relations are duplicated or read separately. The bill follows the reads per page. |
| Keep Aurora on AWS, call it across clouds | +~30–40 ms per query (us-central1 → us-east-1), several queries per request; plus Aurora's ~15 s resume | AWS side unchanged ($0.30) + egress from AWS at $0.09/GB | Aurora is private (`PubliclyAccessible: false`). It would have to be made public or reached through a VPN, which changes AWS and widens its attack surface. |

We chose **Cloud SQL, running**, because the lab's core is "the same app on
another cloud": the relational schema moves without a line of data-access code
changing. The price, about $9.40 a month, comes out of the trial credit, and
`make gcp-db-stop` brings it to $1.70 between demos. Firestore would be the
right answer if this ran for years at zero traffic, and the wrong one for a
lab whose point is comparing like with like.

**Data.** Aurora is private, so a `pg_dump` would have needed a bastion or a
Lambda inside the AWS VPC, which changes AWS. Instead the API runs the Alembic
migrations on start (`RUN_MIGRATIONS_ON_START=true`, idempotent) and inserts
the same demo meetings for today as on AWS (`SEED_DEMO_DATA=true`, only when
the table is empty). The data is the demo seed, not a copy of production.

### E-mail

The weekly report's mailer stays on AWS, so it keeps **SES** with the owner's
verified Gmail address, and no API key exists at all: the mailer Lambda sends
with its IAM role.

When the report moves to Cloud Run, the plan is to keep SES (a multicloud
architecture is allowed) without a key: an AWS IAM role that trusts Google's
OIDC tokens for the report's service account (`AssumeRoleWithWebIdentity`),
the mirror image of WIF. If a provider such as SendGrid or Mailgun is chosen
instead, its API key goes into Secret Manager as its own secret, generated or
pasted once, readable only by the report's service account. It is never in
the repository, in `.env` or in Terraform variables in plain text.

### What we do not move, and why

- **Sign-in (Cognito + Google).** The user pool holds real accounts. Cognito
  cannot export password hashes, so moving to Identity Platform means every
  user signs up again or a migration trigger runs during the transition. The
  API would also verify a different kind of token. The GCP site is therefore
  built without sign-in; the meetings API was already public on AWS.
- **The weekly report** (Scheduler → SQS → builder → S3 → mailer → SES). Five
  services that work together and depend on e-mail. It is the largest rewrite
  (Pub/Sub, Eventarc, Cloud Scheduler) for a feature that runs once a week.
- **Paste an agenda (Bedrock, Claude).** The trial credit does not pay for
  Claude on Vertex AI, and moving to Gemini means re-evaluating the prompt and
  the output validation from ADR 0006. On GCP the site is built without it.
- **WAF and the custom domain.** No free equivalent without a load balancer.

## Consequences

- The core runs on both clouds from one repository: `make gcp-deploy` and
  `make gcp-deploy-frontend` for Google Cloud; the AWS targets are unchanged.
- The idle GCP bill is about $9.40 a month, against about $0.30 on AWS. The
  difference is one line: Cloud SQL does not pause. `make gcp-db-stop`
  removes all of it but the disk, at the price of a database that is down.
- Lock-in sits in the managed services around compute, not in compute: the
  container moved without changes (Mangum was the only Lambda-specific part),
  the database moved without code changes because both clouds offer
  PostgreSQL, while Cognito, SQS, EventBridge, SES and Bedrock each need a
  rewrite or a cross-cloud call.
- The Cloud Run service and the Cloud SQL instance have deletion protection
  until grading. `terraform destroy` needs both flags turned off first (see the
  README).
